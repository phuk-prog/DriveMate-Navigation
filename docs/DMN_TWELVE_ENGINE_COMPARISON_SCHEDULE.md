# Twelve-reference staged execution register — 15 October 2026

This register answers **when** the 12 reference systems are evaluated: **from now, alongside DMN development, using one category at a time**. It is not contingent on a finished engine or APK. Measure every executable comparable provider now, add each unavailable provider only after lawful access is established, and continue comparisons following every relevant component change. An engine's name alone is not test evidence.

## Stage schedule (dependency-based, not a promised clock date)

1. **Immediate, GPS foundation:** fix the current temporal matcher CI regression; run existing identical public UK geometry-derived simulated GPS observations against DMN single-fix and temporal candidate, preserving counts of confident-correct / confidently-wrong / ambiguous / unsupported. This is an internal A/B comparison only.
2. **First externally comparable GPS batch:** make live reproducible map-matching adapters (not merely routing adapters) for **OSRM Match, Valhalla trace matching, GraphHopper map matching**, with identical fixed public UK OSM data and exactly the same nonpersonal injected test observations. First probe actual supported endpoints and map/profile comparability; never guess availability or count an unsupported engine as having failed. Treat OSRM CH/MLD as one family, though they are separate routing configurations.
3. **Expand legal/offline references:** assess runnability of **OsmAnd, Organic Maps, BRouter and openrouteservice** for the *same exact feature* before comparing. If an engine only provides route calculation, rank it in routing, not GPS matching, and mark feature-specific GPS support unknown/unsupported. Reuse historical 100 Wigan matched-route comparisons with version/snapshot evidence, and add held-out UK junction cohorts.
4. **Commercial/provider observation tier:** **HERE, Mapbox, TomTom, Google Maps and Waze** are in the twelve-family portfolio, but may lack licensing, free API access or legally exposed internal positioning controls. Do not make paid calls, scrape apps, spoof internal interfaces, or score inaccessible GPS functions. Use only explicitly authorized legal observation or vendor-approved APIs, with a separately labeled evidence tier; no synthetic scores or equal-snapshot speed claims.
5. **Every subsequent DMN change:** rerun focused DMN vs executable references, then neighboring modules and held-out full start-to-arrival journeys, independent legality oracles and Android isolated-emulator validation. Scores out of ten only on sufficiently extensive equivalent independent truth; retain all unknowns and historic failures.

**Exact cohort:** real UK public OSM snapshot/geofabrik hash, passenger-car profile, same fixed source/target or injected sample, expected source truth, source checksums, engine binary/version, CPU worker and warm/cold timing separated; confidence classification and denominator by category. OSM geometric source for injection is not independently surveyed GPS truth. Cost control: one opt-in heavyweight external CI workflow at a time; reuse cached map build if possible. Work in `DriveMate-Navigation` draft research PR only, keeping production `DriveMate` untouched and no APK release.

## Baseline evidence as of this register

- Historic **DMN, Valhalla, OSRM CH/MLD and GraphHopper** UK car-routing comparisons exist, including 100 Wigan scenarios in the engine-first programme. These were **routing** experiments, not full GPS vs twelve-provider comparisons.
- The latest single-fix DMN public geometry replay on [CI 38739434272](https://github.com/phuk-prog/DriveMate-Navigation/actions/runs/38739434272) reported 74/90 confident correct, 0 confident wrong, 16 ambiguous; 20/30 moving bidirectional withheld. It was map-derived injected GPS, not field truth.
- Existing `benchmarks/public_temporal_gps.py` supports a **DMN vs DMN** temporal replay, but a successful real UK run and independent external map-matching endpoints need separate validation. The new `gps/temporal.py` is an additional experimental topology matcher with strict motion limits; no unverified improvement is assumed.

The list of twelve families and provider limitations is [DMN_TEN_REFERENCE_PROTOCOL.md](DMN_TEN_REFERENCE_PROTOCOL.md). Provider access checks are a **capability matrix**, not a claim all 12 ran or that missing tests have passed.
